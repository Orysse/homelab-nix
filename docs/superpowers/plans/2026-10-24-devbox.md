# Devbox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A NixOS microVM `devbox` on nuc1, reachable over the tailnet, that opens in a tmux "agent board" with Claude Code, opencode, git, and the owner's tmux and vim.

**Architecture:** The devbox reuses the kube nodes' microVM guest module without k3s, declared in a new `devboxes` section of the topology. Home and Tailscale state live on `/srv/data/devbox` through virtiofs. The board is a set of small shell tools over JSON status files, with no service.

**Tech Stack:** Nix (flake-parts, import-tree, microvm.nix, deploy-rs), shell (`writeShellApplication`, jq, fzf, tmux), Tailscale/Headscale, OpenBao (`bao` CLI, `sso/oidc`).

**Spec:** `docs/superpowers/specs/2026-10-24-devbox-design.md`

## Global Constraints

- Guest RAM is `mem = 2500`; the user slice has `MemoryMax=2G`; balloon on; zram swap and `vm.swappiness=10` as in `modules/vm/microvm-guest.nix`. Never exactly 2048 MB. No change to kube-1/2/3 sizes, limits or reservations.
- Deploy only if nuc1's `MemAvailable` is at least 4 GB; otherwise stop and report.
- The VM root is tmpfs. State only under `/srv/data/devbox/{home,tailscale}`. No secret in the repository except sops-encrypted; no long-lived API key on disk in the VM.
- SSH inside the guest accepts only `tailscale0` and the source `192.168.1.200` (nuc1). Never the whole LAN.
- `nix flake check` and `nix build .#nixosConfigurations.nuc1.config.system.build.toplevel` pass at the end of every task. CI has no credentials for private repositories.
- Deploys never restart VMs by themselves (`restartIfChanged = false`); start and restart the devbox by hand.
- Commit only when the owner asks. When asked: stage explicit files (never `git commit -a`, the owner has parallel uncommitted edits in `docs/00-architecture.md` and `modules/host/ddns.nix`), and no Co-Authored-By trailer.
- Identifiers, options and commands stay in English; the repository follows the dendritic pattern (one file, one responsibility, `flake.modules.nixos.<name>`, no hard-coded file lists). Files that are not flake-parts modules live in a `_`-prefixed path or are non-`.nix` files.

## Review Focus

- Two writers update the same status row at once (hook plus `agent-run` trap): the row stays valid JSON, never half-written.
- A remote caller sends a hostile `SSH_ORIGINAL_COMMAND` (newlines, `;`, `$(...)`, `../` in the id, 1 MB task): rejected or sanitised, nothing executed.
- A status file is empty, truncated or not JSON; the status directory is missing: the board shows a `?` row or an empty table, never crashes.
- Non-interactive logins (`scp`, `rsync`, `ssh devbox cmd`) must not start tmux or print anything; a second interactive login attaches to the same session instead of nesting.
- OpenBao is sealed, unreachable, or the OIDC login is cancelled: `devbox-secrets` fails with a clear message and leaves no partial or stale env file.

### Task 6: `agent-status` and the remote-safe wrapper

**Files:**
- Create: `modules/devbox/agent-board.nix`, `modules/devbox/board/agent-status.sh`, `modules/devbox/board/agent-status-remote.sh`, `modules/devbox/board/tests/agent-status.sh`

**Interfaces:**
- Produces (packages in `perSystem.packages`, installed by `devbox-tools`):
  - `agent-status set --id ID [--agent A] [--machine M] [--task T] [--state S] [--pid N] [--window W] [--log PATH]`: creates or merges one row; `since` changes only when `state` changes; `updated` always. Writes `$AGENT_STATUS_DIR/ID.json` (default `~/.local/state/agents`) via temp file and atomic rename, under `flock`.
  - `agent-status list [--json]`: tab-separated `id agent machine task state age`, rows sorted by `updated` descending; an unreadable file yields a row `<file>\t?\t?\t?\t?\t?`.
  - `agent-status rm ID`; `agent-status reconcile`: rows of the local machine in state `working` or `waiting` whose `pid` is not alive become `lost`.
  - `agent-status-remote`: reads `SSH_ORIGINAL_COMMAND`; accepts only `agent-status set <flags above>`; parses into an array and `exec`s `agent-status` without a shell; rejects everything else with exit 2.
- Row schema: `{id, agent, machine, task, state, since, updated, pid, window, log}` with times as epoch seconds. States: `scheduled working waiting done failed skipped lost stopped`. `ID` matches `^[a-z0-9][a-z0-9._-]{0,63}$`; `task` ≤ 200 characters, no control characters.
